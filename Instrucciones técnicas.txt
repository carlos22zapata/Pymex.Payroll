Documentación Técnica: Arquitectura del Motor de Nómina "ToolTips"
Este documento consolida la arquitectura técnica, el modelo de datos y el flujo operativo del módulo de nómina para el sistema administrativo ToolTips. Está diseñado como referencia unificada para el desarrollo del backend en .NET Core 10 (C#) sobre base de datos PostgreSQL y la implementación del frontend en React.

1. Topología del Sistema y Conceptos Clave
El sistema emplea un diseño de reglas dinámicas inspiradas en legislaciones laborales complejas (como la LOTTT en Venezuela). La premisa principal es aislar el código fuente (C#) de las fórmulas matemáticas, trasladando la lógica de cálculo a la base de datos a través de un Motor de Fórmulas Dinámicas.

Variables (Insumos): Son los valores base (sueldo, días trabajados, % de retención).

Conceptos (Resultados): Son las reglas matemáticas que consumen variables para generar las líneas del recibo de pago (Asignaciones o Deducciones).

Contratos (Plantillas): Agrupadores lógicos que dictan qué Conceptos aplican a un grupo específico de Trabajadores.

2. Diccionario de Datos: Enumeradores (Enums)
Ubicación: Pymex.Payroll.Domain.Enums

C#
// Define el impacto financiero en el recibo de pago
public enum ConceptType
{
    Earning = 1,       // Asignación (Suma al neto)
    Deduction = 2,     // Deducción (Resta al neto, origen interno)
    Withholding = 3,   // Retención (Resta al neto, origen legal/impuestos)
    Other = 4          // Provisión/Aporte Patronal (No afecta el neto del empleado)
}

// Define el comportamiento de una Variable tras el "Cierre de Nómina"
public enum PersistenceBehavior
{
    Fixed = 1,         // Fijo: Mantiene el valor para la siguiente nómina (Ej: % ISLR)
    Volatile = 2,      // No Fijo: Se resetea a "0" o "" tras el cierre (Ej: Horas extras)
    Calculated = 3     // No Editable: El sistema lo calcula, el usuario no lo ingresa (Ej: Antigüedad)
}

// Define el tipo de dato para el casteo seguro al evaluar fórmulas
public enum VariableDataType
{
    Numeric = 1,
    Alphanumeric = 2,
    Date = 3
}
3. Modelo de Entidades (Entity Framework Core)
Todas las entidades heredan de AuditableEntity para trazabilidad estricta de auditoría en la base de datos PostgreSQL.

3.1. Entidades de Clasificación y Plantillas

public abstract class AuditableEntity
{
    public DateTime CreatedAt { get; set; } = DateTime.UtcNow;
    public string? CreatedBy { get; set; }
    public DateTime? LastModifiedAt { get; set; }
    public string? LastModifiedBy { get; set; }
}

    public virtual ICollection<ContractConcept> ContractConcepts { get; set; } = new List<ContractConcept>();
}

3.3. Motor Dinámico: Variables y Conceptos
C#
// Catálogo de Insumos (Variables)
public class PayrollVariable : AuditableEntity
{
    [Key] public int Id { get; set; }
    [Required, StringLength(20)] public string Code { get; set; } = string.Empty; // Ej: "V_DIAS_TRAB"
    [Required, StringLength(100)] public string Name { get; set; } = string.Empty;
    public VariableDataType DataType { get; set; }
    public PersistenceBehavior Behavior { get; set; }
}

// Valores de insumo por trabajador
public class EmployeeVariable : AuditableEntity
{
    [Key] public int Id { get; set; }
    public int EmployeeId { get; set; }
    public virtual Employee Employee { get; set; } = null!;
    public int PayrollVariableId { get; set; }
    public virtual PayrollVariable PayrollVariable { get; set; } = null!;
    
    [Required, StringLength(500)] 
    public string Value { get; set; } = string.Empty; // Se castea según DataType
}

// Catálogo de Reglas y Fórmulas
public class PayrollConcept : AuditableEntity
{
    [Key] public int Id { get; set; }
    [Required, StringLength(20)] public string Code { get; set; } = string.Empty; // Ej: "C_QUINCENA"
    [Required, StringLength(100)] public string Name { get; set; } = string.Empty; 
    [Required] public ConceptType ConceptType { get; set; } 
    public bool IsTaxable { get; set; }

    // El string matemático a evaluar. Utiliza los códigos de las variables entre corchetes.
    // Ej: "([V_SUELDO_M] / 30) * [V_DIAS_TRAB]"
    [Required, StringLength(1000)] public string Formula { get; set; } = string.Empty;
}

// Puente entre la Plantilla (Contract) y la Regla (PayrollConcept)
public class ContractConcept : AuditableEntity
{
    [Key] public int Id { get; set; }
    public int ContractId { get; set; }
    public virtual Contract Contract { get; set; } = null!;
    public int PayrollConceptId { get; set; }
    public virtual PayrollConcept PayrollConcept { get; set; } = null!;
    public bool IsActive { get; set; } = true;
}
4. Lógica Operativa del Backend (.NET Core 10)
4.1. Traducción y Evaluación de Fórmulas
El servicio de cálculo (PayrollCalculationService) debe ejecutar las siguientes rutinas para cada Employee activo durante un periodo de nómina:

Obtener el ContractId del trabajador.

Recuperar la lista de PayrollConcept asociados mediante ContractConcept.

Para cada concepto, aplicar una expresión regular (@"\[(.*?)\]") sobre el campo Formula para extraer los identificadores de variables.

Consultar la tabla EmployeeVariable y reemplazar los identificadores en el string por los valores reales del trabajador.

Ejecutar el string resultante (ej. " (3000 / 30) * 15 ") utilizando una librería evaluadora (se recomienda NCalc).

Clasificar el resultado final sumando o restando al Neto a Pagar dependiendo del ConceptType.

4.2. Cierre de Nómina (Proceso Crítico)
Una vez procesada y aprobada la nómina, el sistema debe ejecutar una rutina de limpieza para variables Volatile.

Acción: UPDATE EmployeeVariables SET Value = '0' WHERE PayrollVariable.Behavior = 2 (Volatile) AND PayrollVariable.DataType = 1 (Numeric)

Objetivo: Garantizar que en el siguiente periodo no se arrastren valores transitorios como inasistencias u horas extras. Los valores Fixed (ej. porcentajes de retención de ley) permanecen intactos.

5. Especificaciones de Integración para el Frontend (React)
Para garantizar que el flujo de datos coincida con la arquitectura estricta del backend, el desarrollo en React debe seguir estas directrices:

5.1. Módulo: Constructor de Conceptos (UI Visual)
La interfaz para configurar un PayrollConcept debe implementar un lienzo Drag & Drop (utilizando librerías como React Flow o react-beautiful-dnd).

Comportamiento UI: El usuario dispondrá de una paleta con todas las PayrollVariables disponibles, constantes numéricas y operadores aritméticos (+, -, *, /, ()).

Mapeo Lógico: Aunque la interfaz muestre una representación amigable (caja verde con el texto "Sueldo Mensual"), el estado (state) del componente en React debe construir la fórmula utilizando el Code de la variable encerrado en corchetes.

Payload Esperado (POST a /api/payrollconcepts):

JSON
{
  "code": "C_SSO",
  "name": "Retención Seguro Social",
  "conceptType": 3,
  "isTaxable": false,
  "formula": "([V_SUELDO_NORMAL] * 12 / 52) * 0.04 * [V_LUNES_MES]"
}
5.2. Módulo: Carga de Valores por Trabajador
La interfaz de carga de variables (similar a las vistas transaccionales de ERPs) debe presentar un Data Grid reactivo.

Filtros Obligatorios: Pestañas o radio buttons para filtrar por PersistenceBehavior: Fijos, No Fijos (Volátiles) y No Editables (Calculados).

Bloqueo de UI: Las filas correspondientes a variables con Behavior: Calculated deben estar estrictamente en modo read-only.

Validación: El input de la columna "Valor" debe cambiar su tipo (type="number", type="text", type="date") basado en el VariableDataType provisto por el backend para esa fila.
